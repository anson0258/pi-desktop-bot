# Pi-Desktop 机器人

> 通过飞书、Telegram、微信把手机变成 PI-Desktop 的遥控器：发任务、收结果、回答问题、审阅计划。
>
> 本项目 fork 自 [CJLY-0915/pi-desktop-bot](https://github.com/CJLY-0915/pi-desktop-bot)，感谢原作者的开源分享。
> 本分支在 1.0.1 基础上重点强化了**微信语音输入**与**消息发送可靠性**。

---

## ✨ 本分支解决了什么

原版可用，但在微信通道上有三个会直接影响使用的问题。这一版专门处理它们：

### 1. 微信语音直接变成任务 🎙️

微信的 iLink 协议会在 `voice_item.text` 里给出**云端识别好的文字**，原版没有读取它，语音消息会被静默丢弃。

现在：

- 手机按住说话 → 识别文本 → 派发给 AI，全程无需打字
- 回显一条 `🎙️ 已识别语音："…"` 把识别结果显示出来给你看，**任务同时派发**，不需要你确认
- 识别失败给明确提示，不会把占位文案当指令传给 AI
- 只在**已授权私聊**回显，未授权用户和群消息不响应，避免暴露 bot 在监听

> 这是"白捡"的能力：文字由微信云端识别，插件零成本、不耗 Token、不加延迟。
> 对比飞书：飞书语音消息只给 `file_key`，要做同样的事得自建 ASR 服务。

### 2. 回复令牌失效不再哑火 🔑

微信的 `context_token`（回信令牌）**只活 1.6～6 分钟**，且只能靠"用户再发一条消息"刷新，接口里没有任何续期手段。

原先令牌一旦过期，后续所有发送都失败，面板只抛一串 `ret=-2 prepare failed`，重试也必然失败。

现在：

| 情况 | 行为 |
|---|---|
| `ret=-2`（会话令牌失效） | 立即作废本地令牌 + 提示「微信会话已过期，请在微信给机器人发一条消息后再试」 |
| `-14 / 401`（bot 登录失效） | 提示「微信登录已失效，请重新扫码登录」，不停轮询以保留自动恢复 |
| 发送失败 | 记录 `context_token` 年龄与错误码，一眼能判断是真过期还是别的原因 |

### 3. 长回复会断，但断了就丢了，不会污染后面的对话 📨

AI 生成一条长回复要 3~5 分钟，而令牌窗口比这更短——分片发到中途必然踩过失效点。

原版把失败内容存下来，**必须在面板手动点「重试发送」才会补发**，不点就不会发。但重试时用的仍是同一个已经失效的令牌，所以大概率依然失败，那条记录会一直挂在面板上。

本分支试过更进一步：新消息到达时自动补发旧内容。实测发现旧内容会和新的答复叠在一起，分不清哪段在回答哪个问题，因此放弃了这条路。

现在的处理是**明确丢弃**：

- **分片长度 800 → 1200 字**，请求数减少约 40%，能一次发完的尽量发完
- **断了就直接丢**：不落盘、不补发、不提供「重试发送」
- 面板只显示「消息投递失败：微信会话已过期」，告诉你这条没发出去，然后翻篇
- 修复了「本轮什么都没发，面板却报结果发送失败」的误报

> 💡 **预期会有长回复时，优先用飞书。** 飞书的 `tenant_access_token` 有效期 2 小时且可主动刷新，不会发到一半断掉；微信适合短问答和语音输入，长报告、多工具过程这类内容建议直接看飞书。

### 4. 出错时看得见 🔍

- 审计日志原先只写 `weixin poll failed`，**错误详情被丢弃**；现在完整落盘
- 面板状态文案中文化，不再直接暴露协议原始错误

## 🎯 为什么不用现成方案

| 方案 | 问题 |
|---|---|
| **Anywhere 面板**（`pi.agents-anywhere`） | 本质是外部中继平台的客户端，平台不可达即失效，且需要广域网络权限 |
| **第三方微信网关**（openclaw 等） | 扫码登录易掉线，消息经过第三方服务器 |
| **本插件** | 零第三方中继，只连官方开放平台；长连接 / Stream / 长轮询模式**不需要公网 URL、不需要自建服务器** |

## 📦 安装

**开发期方式**：把本目录复制到

```
C:\Users\<你>\.pi-desktop\plugins\installed\pi.mobile-remote-control
```

或在 PI-Desktop 插件页直接导入，然后重启 PI-Desktop，命令面板执行 `Pi-Desktop 机器人: 打开控制面板`。

安装包已内置二维码与通道 SDK 的运行依赖，**无需在安装目录执行 `npm install`**。控制面板默认 680×840 独立窗口，窄屏自动调整布局并支持纵向滚动。

## 🔌 接入渠道

面板选渠道，在「连接机器人」卡里完成接入：

| 渠道 | 接入方式 | 语音 | 富媒体 |
|---|---|---|---|
| **飞书** | 点「扫码创建」→ 飞书扫码并建应用 | ❌ 需自建 ASR | ✅ 图片 / 文件 |
| **微信** | 点「扫码登录」→ 微信扫码确认 | ✅ **语音转文字** | ❌ 不支持上传 |
| **Telegram** | 走 [@BotFather](https://t.me/BotFather) 取 Token | ❌ | ✅ 图片 / 文件 |
| **钉钉** | 即将支持，面板暂不提供入口 | — | — |

完成后手机端私聊机器人发 `/bind <绑定码>` 绑定（绑定码 10 分钟有效），面板检测到绑定成功会自动收起命令并显示「已连通」。

**凭据只存在本机插件数据目录。**「解绑」只撤销聊天授权与会话关联、保留登录凭据；「清除登录凭据」才会删除。各渠道可同时启用，互不影响。

> ⚠️ **微信两个实现不要同时开**：Pi-WechatBot 与本插件若同时轮询同一个 iLink Bot 账号，会互相抢占导致 HTTP 412。

## 💬 使用

常用命令只保留两组：

```text
会话
/新建 [标题]     新建并关联会话
/会话            选择已有会话
/状态            查看当前会话、工作区和模型
/停止            中断当前任务

配置
/项目            选择工作区（已有会话不会移动）
/模型            先选服务商，再选模型
/思考            选择当前模型支持的思考等级
```

其余在 `/帮助 更多`：

```text
/模式            选择 Agent / Plan / Goal
/权限            选择会话权限模式
/回复            标准、完整或摘要（仅微信、Telegram）
/改动            查看桌面工作区改动
/发送 <路径>     把本机文件发到手机（仅飞书、Telegram）
/解绑            解除会话关联，保留聊天授权
/定时            查看定时任务用法（间隔/每日/暂停/恢复/删除）
```

菜单可点按钮或回数字，`/取消` 或 `0` 退出。中文主命令之外，英文原命令与别名继续兼容：`/help`、`/help more`、`/new`、`/clear`、`/task`、`/切换`、`/use`、`/sessions`、`/status`、`/project`、`/workspace`、`/model`、`/think`、`/thoughtlevel`、`/mode`、`/permission`、`/reply`、`/stop`、`/cancel`、`/diff`、`/send`、`/unbind`。

## 🎛 回复颗粒度

按渠道独立保存，修改从下一轮生效：

| 模式 | 微信 / Telegram | 飞书 |
|---|---|---|
| **标准** | 正文 + 文件变更，隐藏工具过程 | 固定 Card JSON 2.0 流式卡片 |
| **完整** | 正文 + 工具调用进度 + 文件变更 | 同上 |
| **摘要** | 只发最终结果 + 变更摘要 | 同上 |

飞书卡片运行中保留正文与工具摘要顺序，结束态为 `⏳ 运行中 / ✅ 已完成 / ❌ 已终止`；结束后把过程说明折叠进「执行过程」，最终答复、错误提示和文件变更单独展示。工具摘要格式为「状态 · 工具 · 执行命令/路径」，命令自动脱敏截断，**不转发完整工具输出**。

## 🔒 安全模型

- 默认要求绑定码，未绑定聊天仅可用 `/bind`，不能派发任务
- 每聊天令牌桶限速（默认 12 条/分钟），排队上限可配
- 出站文本自动脱敏（token / password / api_key / JWT）
- `manifest.net.domains` 显式声明所需平台域名，无 `net.anyHost`
- 全部远程指令写入审计日志（`audit.jsonl`，512KB 滚动）
- 图片与文件通过宿主正式附件字段提交，不是只把本机路径拼进文本

> 域名声明属于**约定与审计**，Node HTTP/SDK 流量不经过宿主网络沙箱，不构成强制隔离。

## ⚠️ 已知限制

### 微信令牌窗口（平台限制，无法根治）

`context_token` 实测 1.6～6 分钟失效，且**只能靠用户发消息刷新**：

```
用户提问 → T0 拿到令牌
          ↓（1.6~6 分钟窗口）
          第 1 片 ✅   第 2 片 ✅/❌   第 3 片 ❌
```

已实测确认 `/getconfig` **不返回新 token**（响应只有 `ret` 和 `typing_ticket`），"主动续期"路线不可行。当前策略是**降低伤害**：合并分片、失败即弃（不补发）。

**对长回复，微信注定会断在半路：后面的内容直接丢失，只能靠你再问一次让它重新回答。**

对比飞书：`tenant_access_token` 有效期 2 小时且可主动刷新，不存在此类问题。

### 其他

- 钉钉接入 UI 暂未开放；微信通道不支持媒体上传（`/send` 会返回明确错误）
- 原生工具权限请求无法在手机逐项批准，仍需桌面处理；`ask_phone` 只处理业务问答，不替代权限批准
- Telegram 需本机能直连 `api.telegram.org`；微信 iLink Bot 需平台侧具备 Bot 开通资格
- 附件单条最多 4 个、单文件 5 MiB，超限整条拒绝
- 微信上下文只对授权私聊持久化，群消息不更新；无群协作与话题功能
- 插件日程与宿主定时页分别管理，不自动匹配宿主已有结果
- 发送失败的内容直接丢弃：不落盘、不补发，面板只显示错误原因

## 🧩 项目结构

```text
main.js                      装配：生命周期、服务注册、面板 RPC
scripts/build-vendor.cjs     构建随包依赖，避免安装时依赖 node_modules
scripts/smoke-plugin.cjs     安装隔离检查（不连接真实平台）
vendor/                      随包 SDK、二维码实现与第三方许可信息

lib/bridge.cjs               桥接核心：指令路由、会话队列、分片发送、审批轮询
lib/channel.cjs              通道接口与工厂
lib/bot-commands.cjs         中文别名、分页菜单与宿主配置命令
lib/weixin.cjs               微信 iLink 适配器（长轮询 + 语音取文 + CDN AES 解密）
lib/weixin-registration.cjs  微信扫码登录（device-code 流程）
lib/feishu.cjs               飞书适配器（WSClient 长连接）
lib/feishu-api.cjs           飞书 API（tenant token 缓存、发消息、媒体）
lib/feishu-card.cjs          流式卡片：Card JSON 2.0、元素预算分段、写失败断路器
lib/feishu-registration.cjs  飞书扫码建应用
lib/dingtalk.cjs             钉钉适配器（DWClient Stream）
lib/telegram.cjs             Telegram 适配器（Bot API 长轮询 + 内联按钮）
lib/security.cjs             配对码、白名单、限速、脱敏
lib/store.cjs                持久化（配对/绑定/凭据/审计/失败结果）
lib/render.cjs               结果分段与文本渲染
lib/ipc.cjs                  Agent 扩展 ↔ 插件主进程事件通道
extensions/agent.js          Agent 进程内扩展
renderer/index.html          控制面板结构
renderer/style.css           布局、状态与响应式样式
renderer/app.js              渠道接入、扫码及绑定状态
```

## 🛠 开发与测试

```powershell
npm ci               # 开发环境依赖
npm run build        # 生成随包 vendor 与第三方许可信息
npm test             # 含无 node_modules 的安装隔离测试
```

**注意**：`distribution.test.cjs` 在**含中文或空格的路径**下会崩溃（Windows 下 `spawnSync` 子进程问题），请把仓库放在纯英文路径再跑全量测试。

发布前先构建、跑测试，再用 PluginCheck / PluginPack 校验打包；将安装包解压到干净目录执行 `node scripts/smoke-plugin.cjs .`，确认主入口、二维码、SDK 与初始化不依赖外部 npm 模块。这不替代真实宿主和平台的收发验收。

升级后如新增权限（如 `shell.openExternal`、`clipboard.write`），需在插件管理页**重新加载插件**，权限不会通过热更新自动授予。
